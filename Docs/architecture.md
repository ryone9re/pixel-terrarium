# アーキテクチャ

## 状態と景色の分離

`TerrariumCore`はFoundationだけに依存し、育成計算、手続き型レイアウト、Widget用スナップショットを提供します。

**手続き型レイアウト**は、テラリウム固有のシード、成長ポイント、水分量から苔、シダ、石、朽木、水滴の配置を算出した値です。
乱数生成器をシードで初期化するため、同じ入力からは同じ配置を再現します。
成長時は既存の苔の位置を保ったまま、群生数、半径、高さ、シダの葉数を増やします。

## アプリの描画

アプリ本体はSwiftDataで育成状態を保存します。
RealityKitはBlender製の共通外装を読み込み、手続き型レイアウトから容器内のModelEntityを組み立てます。
容器の底は排水層、炭、土、非対称に盛り上がる苔面の順に重ね、平らな円盤に見えない地形を作ります。
苔と石は、少数の共有メッシュをシード付きで使い分けることで、真球ではない有機的な輪郭を作ります。
モデルを景色ごとに書き出さないため、成長に応じて群落を追加してもアプリ容量は増えません。

土、苔、石、枝、葉、金属、ガラスにはRealityKitのPBR材質を使います。
水分が40以上になると苔と石の粗さ、反射、クリアコートが変化し、ガラス前面には透明な3D水滴を配置します。
夜間は暖色のキーライト、容器内のランタン光、青色のリムライトを組み合わせ、水滴と微粒子だけに強い輝きを与えます。
苔本体の反射は抑え、濡れた植物がプラスチックに見えない範囲へ留めます。

有機メッシュは苔房5種類、石4種類、シダ、傾斜地形、朽木を初回生成後にキャッシュします。
苔は5つの小さな葉状塊を1メッシュへ結合し、最大22房に抑えます。
シダも茎と小葉を1枚のフロンドごとに結合し、最大6 ModelEntityに抑えます。
これにより細かな輪郭を増やしながら、成熟時の回転に必要なEntity更新数を以前の数百個から数十個へ減らします。

苔のPBR材質には、実写調のマクロ表面を元にした専用アルベドテクスチャを使います。
濡れた石だけに控えめなクリアコートを与え、ガラスは低い面不透明度、縦方向の反射、薄い結露、水滴を別々に重ねます。
接地感は方向光の影と、地形の高低に沿った配置で補います。

## Widgetの3Dスナップショット

アプリはApp Groupへ、シードと育成状態をJSONで原子的に書き込みます。
同時に、アプリ画面と同じ`TerrariumSceneFactory`からRealityKitの景色を組み立て、朝、昼、夕方、夜の4種類を透過PNGとして保存します。
Widgetは表示時刻に合う画像を読み取るため、苔、石、シダ、ガラス、水滴、台座、照明がアプリと一致します。

PNGがまだ生成されていない初回表示だけは、JSONからSwiftUI Canvasの景色を再構成します。
画像生成はアプリ起動時、日付解決時、水やり時に非同期で実行し、原子的な書き込みが完了してからWidgetのタイムラインを再読み込みします。
Widgetは保存済みの育成状態を表示し、日付をまたいだ成長と水分更新は次にアプリが状態を解決した時点で画像と一緒に反映します。

## 更新の流れ

```text
SwiftDataの育成状態
  -> TerrariumCoreの決定的な育成計算
  -> シード付き手続き型レイアウト
     -> 共通のRealityKitシーン
        -> アプリの3D表示
        -> 時間帯別の透過PNG
  -> App GroupのJSONとPNGスナップショット
  -> Widget表示（Canvasは初回のみ）
```
